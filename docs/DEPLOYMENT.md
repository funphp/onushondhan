# Production Deployment — Non-Docker Initial Release

## Target
Linux server with:
- Nginx
- PHP-FPM 8.3+
- MySQL 8+
- Node.js compatible with the selected stable Next.js release
- Composer
- npm/pnpm as selected by the frontend package
- systemd or Supervisor for long-running Node/queue/scheduler processes
- HTTPS certificate

## Deployment principles
- Keep application code outside the direct web root where possible.
- Laravel web root must be `backend/public` only.
- Never expose `.env`, storage internals, logs, or source maps unintentionally.
- Run migrations before switching traffic, using safe migration practices.
- Build frontend assets before activation.
- `php artisan storage:link` only for intentionally public files.
- Use private storage paths for sensitive evidence.

## Suggested deployment flow

```text
1. fetch release
2. install backend dependencies --no-dev
3. install frontend dependencies
4. build frontend
5. verify env/config
6. run safe database migrations
7. run release smoke checks
8. restart PHP-FPM / queue / Next.js service
9. verify health endpoints
10. record release and git SHA
```

## Required production environment variables
See `docs/ENVIRONMENT.md` and `.env.example` generated by the implementation.

## Queue/scheduler
Use a non-Redis queue for the initial deployment. If the application requires durable asynchronous jobs, use the Laravel database queue driver or another explicitly supported non-Redis mechanism.

Scheduler should run `php artisan schedule:run` every minute via cron/systemd timer.

## Health checks
Expose a simple authenticated or non-sensitive health endpoint indicating application/database readiness without revealing secrets or infrastructure details.

## Rollback
Document:
- code rollback;
- database compatibility expectations;
- frontend rollback;
- storage rollback considerations;
- queue restart;
- cache/config reload.

Never automatically roll back a destructive database migration without a tested rollback plan.
